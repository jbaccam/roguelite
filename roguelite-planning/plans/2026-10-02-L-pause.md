# Plan L: pause screen (part 2 of the UI request)

Status: the design was approved by the user on 2026-10-02 from an HTML mockup ("this seems good"), with three changes:
- The background is the run, see-through but darker. The side panels are see-through dark like the new quest tracker, not solid.
- The build has to work late game and in Endless with lots of items. The "Late game (maxed)" mockup shows the worst case fitting.
- Level-ups are the stat cards picked on level-up. Their effect already shows in STATS; the right panel lists them as icons with ×count.

Part 1 is [plan K](2026-10-02-K-quests-power-ui.md). Ground rules are the same: repo first, ask before writing Studio, anchored hunks for shared scripts, and no Play sessions without asking.

## Rules

| Situation | What happens |
|---|---|
| Opening it | The pause button in the run HUD (the user's pause icon), the **P** key, or the Roblox Esc menu opening (`GuiService.MenuOpened`; our screen stays open behind it). |
| Solo | Pausing freezes the run (list below). Resume, or P again, unfreezes it. |
| Party | Your menu opens, but the run only freezes once **every living run member** has paused. Until then the game keeps going and the screen says "2 / 3 PAUSED · THE GAME KEEPS GOING UNTIL EVERYONE PAUSES". A strip shows each player with a ✓ (paused) or "playing". |
| Unfreezing | Any living member pressing Resume unfreezes it for everyone. Their menu closes; the others' stay open until they resume or close them. |
| Who counts | Living members only. Downed players don't block a freeze. With nobody alive, the last stand already holds the run, and pausing does nothing more. |
| Shop phase | Pausing in the shop freezes the shop countdown (`ShopEndsAt`) the same way. |
| Limits | None. A freeze needs everyone, so nobody can freeze a party alone. |
| Developers | P opened the admin panel. That moves to **F2** so P can be pause for everyone. |

## What a freeze stops

From the research map of every run loop (Studio and repo):

| Thing | How it's frozen |
|---|---|
| Wave clock | `ShopService.pause()` / `resume()`. `resume` also refuses while `RunPaused` is set, like it does for `AdminPaused`, so a revive can't restart the clock mid-freeze. |
| Shop countdown | `ShopEndsAt` keeps its time left and is set again on unfreeze; `shopTimeUp` returns while frozen. |
| Spawner | `queueSpawn` and the spawn telegraph check `RunPaused` next to `AdminPaused`. The refill-on-clear listens to both. |
| Enemies | The chase loop's freeze check becomes `AdminFreeze or RunPaused`: no moving, attacks in progress cancelled. They wind up again after the freeze, so nothing lands the instant it ends. |
| Enemy shots in flight | `EnemyAttacks` stops stepping them while frozen; they hang in the air and carry on afterwards. Their lifetime counts frame time, so no time is lost. |
| Map bosses | While frozen, MapBossService cancels the attack in progress, clears shots and follow-ups, and holds still. The check runs **before** those step, unlike AdminFreeze today. |
| Hammer boss | The same in `BossService`. That script exists **only in Studio**, so it's copied into the repo first (`combat/bosses/BossService.luau`). |
| Player weapons | Each member's `WeaponEnabled` is turned off and restored to what it was. Shots in flight end, as they already do when weapons switch off. |
| Players | They can't move or jump (the shop-hold path in `CharacterService.applyMoveSpeed`) and take no damage (the `contact` gate). Bump damage and regeneration skip while frozen. |
| Burn, poison, slow | The status loop skips while frozen, and their end times move later by the frozen time. |
| Pets | The ability loop skips while frozen. |
| Heart pickups | Expiry skips and moves later by the frozen time, `ExpiresAt` included, so the blink stays right. |
| Quest minutes | Frozen time doesn't count toward "Play 20 Minutes" or Playtime. |

The flag is the `RunPaused` attribute on `ReplicatedStorage.RogueliteCombat` (where `AdminFreeze` and `ZombiesEnabled` already live). Sandboxed and unsandboxed scripts can both read it.

## Screen (PauseUI)

A `ScreenGui` named `PauseMenu`, DisplayOrder 70: above the HUD (20) and level-up cards (60), under the death screen (80) and results (85). One canvas (`T.canvas`), like the other full-screen screens.

- **Backdrop:** the run, under a dark veil (0.66 opacity). The window chrome is not used.
- **Top:** a "PAUSED" plate with the pause icon and stone caps; then map · difficulty · wave (or "ENDLESS WAVE 63"); then the status pill (lime GAME FROZEN, or amber "n / m PAUSED · THE GAME KEEPS GOING UNTIL EVERYONE PAUSES"); then the party strip in a party.
- **Left, STATS (see-through panel):**
  - the player's effective stats, grouped Offense / Defense / Recovery / Utility, read from the `PlayerStates` attributes;
  - THIS RUN: level, wave, kills, damage dealt;
  - it scrolls when it's taller than the screen.
- **Centre:** RESUME, then SETTINGS (`T.settingsWindow`), RESTART and LEAVE RUN.
  - RESTART is solo-only. It starts the same map and difficulty again and keeps the emeralds earned so far. It uses plan J's Play Again; until that lands it is hidden.
  - LEAVE RUN takes two taps, like the shop's, and uses `RunAction 'LeaveRun'`.
- **Right, build (see-through panel):**
  - WEAPONS: up to 6 in one row, with tier pills;
  - ITEMS: up to 16 kinds, 8 a row, with ×copies;
  - LEVEL-UPS: up to 16 cards, 8 a row, with ×picks, plus "level n · m picks".
  - The worst case fits without scrolling.
- **Phones:** the canvas scales like the Armory. Below the readable scale the side panels stack under the buttons and the body scrolls. `UILayoutAudit.sweep` must pass.

## Data the client needs

| Data | Source |
|---|---|
| Stats | `PlayerStates.<id>` attributes (already published) |
| Weapons, items, level | ShopService's publish payload (already there) |
| Level-up picks | **New:** ShopService adds `upgrades = s.upgradeBonuses` (id → picks) to the same payload |
| Kills and damage this run | **New:** RogueliteMeta keeps per-stint counts next to the quest tallies and sets the `RunKills` / `RunDamage` player attributes once a second |
| Who's paused | **New:** RogueliteMeta sets the `Paused` player attribute and the `RunPausedCount` / `RunLivingCount` attributes on `RogueliteCombat` |

## Server (RogueliteMeta + RunPause)

- `combat/RunPause.luau` (new, ServerScriptService, unsandboxed) is the logic: `set(p, on)`, `update()` and `frozen()`. It is pure enough to test with stub players.
- RogueliteMeta wires it to:
  - `RunAction 'SetPaused'` with a boolean, limited to once every 0.25 s;
  - membership and down changes, player leave, run reset and results.
- Freeze applies the table above. Unfreeze undoes it in reverse order and moves the saved deadlines later by the frozen time.
- A run ending, a run reset, or everyone leaving always clears `RunPaused`. A freeze can never outlive its run.

## 4-player parties (launch work, 2026-10-02)

The strip and the pill now handle 1-4 members: one card each (you first, lime edge) with the name on its own line (long names shrink, then end in "…"), then ✓ paused / playing / down. Downed players get a dimmed card and never count toward "n / m PAUSED". On phones the PAUSED plate and the map line share one centred row, the pill uses shorter words on one line, buttons stay 72 design px tall and the notes are one short line. RESTART follows the server rule (one run member, downed or not). Mockup: `previews/plan-l-mockup/pause.html` (tabs for a 4-player party on PC and phones).
